Self-Healing K8s Agent

An agent that notices when a workload breaks, figures out which change broke it, and opens a fix as a pull request. A human approves it in Telegram, ArgoCD rolls it out, and the agent confirms the problem is gone. If it isn't, the agent reverts its own fix.

detect→diagnose: what changed?→fix as PR→human approves→ArgoCD applies→verify or revert

What the judges see

The 3-minute demo

The judges watch the fix happen live. Each fault is injected as a git commit, the way real incidents start, so the agent's "what changed?" answer points at a real commit.

  1. 0:00 · break it

    Run the chaos script

    It commits a memory limit of 64Mi to the api deployment. ArgoCD syncs it and pods start getting OOMKilled.

  2. 0:20 · detect

    Incident opens

    The watcher sees the CrashLoopBackOff and the scoreboard shows a new red incident.

  3. 0:50 · diagnose

    Root cause in Telegram

    "OOMKilled since commit a1b2c3, which cut the memory limit from 512Mi to 64Mi. Peak usage is 310Mi."

  4. 1:20 · approve

    One click

    The Telegram message shows the PR diff, the validation results and the blast radius. An engineer taps Approve.

  5. 1:40 · verify

    Back to green

    ArgoCD syncs and the rollout completes. The agent watches for 3 minutes, then marks the incident resolved and writes a postmortem.

  6. 2:30 · scale

    Fault barrage

    Five faults are injected at once. The scoreboard shows how many were resolved and the mean time to fix. One fault is deliberately escalated.

Signal ingestion

How problems are detected

No single source sees everything. Five independent detectors feed the same pipeline. All of them are plain code with no LLM. The model only runs after something has been flagged, which keeps detection fast, cheap and predictable.

Some faults are invisible to Kubernetes

A NetworkPolicy that blocks api → redis leaves every pod Running and Ready, with no restarts and no events. Only the prober (timeouts) and the log tail (connection errors) catch it. It's a good demo moment for why there are several detectors.

Disk usage is metrics-only

A PVC object only says Bound and its size, never how full it is. Usage comes from kubelet volume stats (kubelet_volume_stats_used_bytes, inodes) and the built-in KubePersistentVolumeFillingUp alerts: a warning when the trend predicts full in 4 days, critical under 3% free.

Check the demo storage on day 1

kind's default local-path provisioner probably reports no volume stats and can't expand volumes. Install csi-driver-host-path (reports stats, supports expansion) and confirm the metric appears before building the PVC scenario.

Cheap filter before the expensive investigation.

Signal + last 20 events for the workload.
Out
{actionable, category, severity}
Tech
gpt-oss-20b, JSON output, no tools.

LLM client

Agent core
One client, two backends. Swapping is a config change.
API
OpenAI-compatible Chat Completions with tools. Groq and Ollama both serve it.
Config
LLM_BASE_URL, LLM_API_KEY, MODEL_FAST, MODEL_SMART. Groq: https://api.groq.com/openai/v1, openai/gpt-oss-120b. Ollama: http://ollama:11434/v1, gpt-oss:120b.
Does
Own ~150-line tool loop, retries with backoff (Groq rate limits), JSON validation with one repair retry, token + latency logging per call.
Tech
openai Python SDK with a custom base_url. No agent framework.

Investigator

Agent core
Finds the root cause and the change that caused it.
Tools
k8s_get k8s_describe k8s_logs k8s_events prom_query git_log git_diff argocd_history runbook_search. All read-only.
Out
{root_cause, evidence[], suspect_commit, confidence, fix_class}
Tech
gpt-oss-120b through the LLM client, 15 tool-call budget, reasoning effort high.

Fixer + validation gate

Loop
Writes the patch and proves it is safe to propose.
In
Diagnosis + manifests repo checkout.
Gate
kustomize build → kubeconform → kubectl apply --dry-run=server → kyverno apply → blast radius (which Deployments/Services change).
Out
Branch + PR with the diagnosis in the description. A small GitHost interface covers GitHub now and Gitea later (Gitea's API is close to GitHub's).

Telegram approval bot

Loop
The human checkpoint, and the main UI.
Message
Root cause, top 3 evidence lines, suspect commit link, gate results, risk level. The diff goes in a code block; if it's longer than Telegram's 4096-character limit, it's attached as a .diff file.
Buttons
Inline keyboard: Approve (merges PR) · Reject (bot asks for a reason as a reply, goes back to investigator) · Explain more (reply in the same chat).
Access
Posts to one team group chat. Only allowlisted Telegram user IDs can press Approve; everyone else gets "not authorized".
Tech
python-telegram-bot, long polling (no public URL needed at the venue). Behind a Notifier interface so the channel can be swapped.

Verifier

Loop
Closes the loop or undoes the fix.
Checks
ArgoCD app Synced + Healthy, rollout complete, restart count flat, original symptom absent for 3 min (configurable).
Fail
git revert the fix commit, mark ROLLED_BACK → ESCALATED.

Postmortem writer

Loop
Each incident improves the next diagnosis.
Out
Markdown postmortem (timeline, cause, fix, prevention) committed to the runbooks repo. runbook_search finds it next time.

Chaos harness + scoreboard

Demo
The fault catalog, run as a script and shown on a screen.
CLI
chaos inject oom-limit, chaos barrage 5, chaos reset.
Board
Small web page reading SQLite: open incidents, state pills, time to resolve, resolved/total.

Where this ends up

Closed-network path

The target is an air-gapped network. Everything that calls the internet sits behind a small interface, so the move is configuration, not a rewrite.

Same weights on both sides

gpt-oss runs on Groq and in Ollama. Prompts and the fault catalog tuned at the hackathon carry straight over. Test with Ollama on a laptop early (20b runs in about 16 GB) to catch differences in tool-call formatting.

Telegram can't run air-gapped

Telegram's Bot API lives on the public internet. On the closed network the Notifier must point to a self-hosted chat or a web page. Pick one before the hackathon ends so the interface fits it.

GPU sizing

gpt-oss:120b needs roughly 80 GB of GPU memory (one H100 / A100 80GB). gpt-oss:20b fits a 16–24 GB card and can also run investigation if no large GPU is available, with lower accuracy.

Data stays inside

At the hackathon, logs and manifests go to Groq, so only use the demo cluster. On the closed network nothing leaves it.

Guardrails

Read-only identity

The agent's ServiceAccount has a ClusterRole with get/list/watch only, and no access to Secret values.

Writes only through git

Every change is a reviewable PR, merged on human approval and easy to revert.

Fix allowlist

Resources, image tag, env/ConfigMap refs, probes, selectors, replicas, PVC size (at most 2×). Anything else is escalated.

Validation gate

Schema check, server-side dry-run and Kyverno policies all run before a human ever sees the PR.

Scope and rate limits

Namespace allowlist, at most 1 open PR per workload, 5 PRs per hour, 15 tool calls per investigation.

Approver allowlist

Only listed Telegram user IDs can approve or reject. The bot ignores everyone else in the chat.

Untrusted inputs

Logs and events are wrapped as data in prompts and never followed as instructions. Tools cannot write, so a prompt injection in a log has nothing to act on.

"How is this different from k8sgpt or HolmesGPT?"

They explain problems. This system fixes them: it ties the failure to the commit that caused it, ships the fix through GitOps, and proves the fix worked or reverts it.

"What if the agent is wrong?"

It cannot change anything without a merged PR. A wrong fix fails verification and gets reverted automatically.

"Does it work on real clusters?"

It needs only read-only RBAC and a GitOps repo. That is a common production setup.

"Can it run air-gapped?"

Yes. It runs on open-weight models through Ollama, with a self-hosted git server and chat. Nothing leaves the network.

"What does it cost per incident?"

Log tokens per incident on the scoreboard and quote the real number. On the closed network the only cost is the GPU.
