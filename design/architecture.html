Self-Healing K8s Agent

An agent that notices when a workload breaks, figures out which change broke it, and opens a fix as a pull request. A human approves it in Slack, ArgoCD rolls it out, and the agent confirms the problem is gone. If it isn't, the agent reverts its own fix.

detect→diagnose: what changed?→fix as PR→human approves→ArgoCD applies→verify or revert

What the judges see

The 3-minute demo

The judges watch the fix happen live. Each fault is injected as a git commit, the way real incidents start, so the agent's "what changed?" answer points at a real commit.

  1. 0:00 · break it

    Run the chaos script

    It commits a memory limit of 64Mi to the api deployment. ArgoCD syncs it and pods start getting OOMKilled.

  2. 0:20 · detect

    Incident opens

    The watcher sees the CrashLoopBackOff and the scoreboard shows a new red incident.

  3. 0:50 · diagnose

    Root cause in Slack

    "OOMKilled since commit a1b2c3, which cut the memory limit from 512Mi to 64Mi. Peak usage is 310Mi."

  4. 1:20 · approve

    One click

    The Slack card shows the PR diff, the validation results and the blast radius. An engineer clicks Approve.

  5. 1:40 · verify

    Back to green

    ArgoCD syncs and the rollout completes. The agent watches for 3 minutes, then marks the incident resolved and writes a postmortem.

  6. 2:30 · scale

    Fault barrage

    Five faults are injected at once. The scoreboard shows how many were resolved and the mean time to fix. One fault is deliberately escalated.

Fixer + validation gate

Loop
Writes the patch and proves it is safe to propose.

Gate
kustomize build → kubeconform → kubectl apply --dry-run=server → kyverno apply → blast radius (which Deployments/Services change).

Slack approval

Loop
The human checkpoint, and the main UI.

Root cause, top 3 evidence lines, suspect commit link, diff, gate results, risk level.

Verifier

Loop
Closes the loop or undoes the fix.
Checks

Out
Markdown postmortem (timeline, cause, fix, prevention) committed to the runbooks repo. runbook_search finds it next time.

Guardrails

Read-only identity

The agent's ServiceAccount has a ClusterRole with get/list/watch only, and no access to Secret values.

Writes only through git

Every change is a reviewable PR, merged on human approval and easy to revert.

Fix allowlist

Resources, image tag, env/ConfigMap refs, probes, selectors, replicas. Anything else is escalated.

Validation gate

Schema check, server-side dry-run and Kyverno policies all run before a human ever sees the PR.

Scope and rate limits

Namespace allowlist, at most 1 open PR per workload, 5 PRs per hour, 15 tool calls per investigation.

Untrusted inputs

Logs and events are wrapped as data in prompts and never followed as instructions. Tools cannot write, so a prompt injection in a log has nothing to act on.

"How is this different from k8sgpt or HolmesGPT?"

They explain problems. This system fixes them: it ties the failure to the commit that caused it, ships the fix through GitOps, and proves the fix worked or reverts it.

"What if the agent is wrong?"

It cannot change anything without a merged PR. A wrong fix fails verification and gets reverted automatically.

"Does it work on real clusters?"

It needs only read-only RBAC and a GitOps repo. That is a common production setup.

"What does it cost per incident?"

Log tokens per incident on the scoreboard and quote the real number.
